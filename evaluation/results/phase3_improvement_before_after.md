# Phase 3: RAGAS Library Evaluation — Baseline and Improvements

**Financial Multi-Agent System** · Filippo Maria Incecchi · Università degli Studi di Brescia
Analytics and Data Science for Economics and Management · Prof. Angela Locoro

---

## 1. Objective

This document reports the **reproducible RAGAS evaluation** (the actual `ragas`
Python library, not an in-session rubric) of the multi-agent system, and the
**iterative improvements** made in response to it. It records three measured
configurations of the system and what each change contributed.

---

## 2. Method

- **Metrics (reference-free):** faithfulness, answer relevancy, and LLM context
  precision (without reference), from the `ragas` library.
- **Judge LLM:** Claude **Haiku 4.5** via the Anthropic API (~€2.2 per full run).
- **Embeddings for answer relevancy:** local `nomic-embed-text` (Ollama).
- **Data:** the same 100 questions (20 rag, 20 market, 20 macro, 10 × 4 multi),
  each answer regenerated by the system after every change, then scored.
- **Three configurations evaluated:**
  - **v1 — Baseline:** original system — verbose analyst prompts, ChromaDB
    default embedding (all-MiniLM-L6-v2, 384-dim), no reranker.
  - **v2 — + Prompt tightening (+ reranker):** concise, grounded prompts;
    a cross-encoder reranker was also trialled here (still all-MiniLM).
  - **v3 — + Embedding upgrade (final):** `nomic-embed-text` (768-dim) via
    Ollama; the reranker was removed after it showed no effect.

---

## 3. Baseline (v1) — the original system under the library

| Metric | Score |
|---|---|
| Faithfulness | 0.66 |
| Answer relevancy | 0.61 |
| Context precision | 0.50 |
| Faithfulness `NaN` cells | 20 / 100 |

The library is stricter than a holistic judge (it decomposes each answer into
atomic claims and checks every retrieved chunk), so these are lower than a
whole-answer read. Two weaknesses stood out: **low faithfulness/relevancy on the
interpretation-heavy answers** (macro and the multi combinations), and **low
context precision** from imprecise retrieval. Faithfulness was also *unmeasurable*
on 20 long answers (all of `multi_all`), which the judge could not parse.

Baseline by category:

| Category | Faithfulness | Answer relevancy | Context precision |
|---|---|---|---|
| rag | 0.97 | 0.76 | 0.39 |
| market | 0.85 | 0.84 | 1.00 |
| macro | 0.51 | 0.81 | 1.00 |
| multi_rag_market | 0.40 | 0.31 | 0.06 |
| multi_rag_macro | 0.27 | 0.44 | 0.07 |
| multi_market_macro | 0.32 | 0.08 | 0.07 |
| multi_all | — (NaN) | 0.49 | 0.00 |

## 4. Improvement 1 — Prompt tightening (v1 → v2)

**Change.** The synthesizer, market and macro prompts were rewritten to answer
the specific question concisely, use only the figures the agents provide, and
drop free-standing interpretation, investment recommendations, disclaimers and
generic "investors/businesses may…" commentary. (The RAG prompt was already
strict.)

**Effect.**

| Metric (overall) | v1 | v2 | Δ |
|---|---|---|---|
| Faithfulness | 0.66 | **0.89** | **+0.23** |
| Answer relevancy | 0.61 | **0.72** | +0.11 |
| Context precision | 0.50 | 0.50 | ±0.00 |
| Faithfulness `NaN` | 20/100 | **0/100** | −20 |

Faithfulness by category — the gains land exactly on the weak categories:

| Category | v1 | v2 |
|---|---|---|
| macro | 0.51 | **0.87** |
| multi_rag_market | 0.40 | **0.78** |
| multi_rag_macro | 0.27 | **0.87** |
| multi_market_macro | 0.32 | **0.76** |
| multi_all | — (NaN) | **0.93** |

The low "before" scores came from advisory sentences not present in the data;
removing them leaves answers whose claims are grounded in the agents' figures.
As a side effect, the 20 unmeasurable answers became parseable, so `multi_all`
went from *unmeasured* to **0.93**. Context precision, correctly, did not move —
the prompts do not change what is retrieved.

---

## 5. Improvement 2 — Cross-encoder reranker (null result, removed)

**Change.** Retrieval over-fetched 20 candidates and re-ranked them with a small
cross-encoder (`ms-marco-MiniLM`), keeping the top 5.

**Effect: none.** Overall context precision was unchanged (0.497 → 0.499) and RAG
even dipped slightly. The reranker *did* run (18/20 RAG questions received
re-ordered contexts), so this is not a failed install — it reordered the
candidates without ranking them better. The interpretation: the bottleneck is not
the *ordering* of candidates but the **candidate pool** — a general-purpose
embedding over 10-K text, re-ranked by a model trained on web-search passages.

**Decision.** The reranker was **removed** (and its `sentence-transformers`
dependency dropped). The null result is itself informative: it correctly pointed
to the embedding, not re-ranking, as the lever for context precision.

---

## 6. Improvement 3 — Embedding upgrade (v2 → v3, final)

**Change.** The vector store now embeds with `nomic-embed-text` (768-dim) via
Ollama instead of ChromaDB's default all-MiniLM (384-dim). Applying it required
re-indexing the corpus.

**Effect — context precision rises where it should.**

| Category | v2 (all-MiniLM) | v3 (nomic) | Δ |
|---|---|---|---|
| **rag** | 0.35 | **0.51** | **+0.16** |
| multi_rag_macro | 0.05 | 0.22 | +0.17 |
| multi_rag_market | 0.03 | 0.12 | +0.09 |
| multi_market_macro | 0.30 | 0.10 | −0.20 |
| **OVERALL** | 0.50 | **0.54** | **+0.04** |

Pure-RAG context precision — the cleanest signal — rose **0.35 → 0.51** (≈ +47 %
relative), and every rag-involving category improved. Faithfulness (0.89 → 0.87)
and answer relevancy (0.72 → 0.73) held, as expected (the embedding does not
change generation). This **confirms the prediction of Improvement 2**: the fix
for context precision was a better embedding, not a reranker.

*Caveats:* `multi_market_macro` precision fell (its score is dominated by the
market/macro data blocks plus a variable agent mix, not RAG retrieval — category
noise, not an embedding regression); the small faithfulness dip is run-to-run
variance from different retrieved chunks.

## 8. Interpretation — what each lever did

- **Prompt engineering fixed faithfulness and relevancy.** Grounding discipline
  in the prompts — not model scale — closed most of the strict-faithfulness gap
  for a small local model (overall 0.66 → 0.89) and made every answer measurable.
- **The reranker did nothing**, and its null result correctly located the
  retrieval bottleneck upstream.
- **A stronger embedding fixed context precision** where the bottleneck actually
  was (RAG 0.35 → 0.51). This is a clean cause-and-effect chain: hypothesis from
  one experiment, confirmed by the next.
- The two data-grounded agents (market, macro) and the single-agent RAG path
  remain the most reliable; the residual low context precision on the multi
  categories reflects the strictness of the metric on multi-chunk contexts.

---

## 9. Conclusion

Under the reproducible `ragas` library (Claude Haiku 4.5 judge), the system
improved from **faithfulness 0.66 / relevancy 0.61 / context precision 0.50**
(with 20 unmeasurable answers) to **faithfulness 0.87 / relevancy 0.73 /
context precision 0.54** (0 unmeasurable), via two effective changes and one
informative null result: **tightening the generation prompts** raised
faithfulness and relevancy, a **cross-encoder reranker** made no difference and
was removed, and a **stronger embedding** raised context precision. The evaluation
tells a coherent engineering story — each metric was moved by the intervention
that targeted its actual cause — and does so with third-party-reproducible
numbers suitable for the methodology chapter.
